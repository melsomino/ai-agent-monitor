# Settings and setup

<a id="settings-shell"></a>
## Window, navigation, and sizing

M: Settings replaces the session list and quota footer **inside the existing status-menu window**. It creates no separate window and does not activate a normal preferences window. The retained shell has a Sessions back button, Settings title, version, and icon-and-label tabs General (gear), Applications (grid), Agents (robot), Telegram (paper plane), Web (network). Content width460pt; header starts17pt from the top, navigation68pt with81.6×66pt targets and4pt gaps; pane content starts150pt. Header and navigation scroll with the pane. Pane height plus166pt determines the requested popup height, subject to the usual screen/Dock maximum. Overflow uses a transparent nonelastic vertical scroller. Navigation and Sessions use shared glass hover/focus surfaces. Pane action buttons use the same glass action treatment: 12pt medium captions, 12pt corner radius, muted violet fill and fine rim, shared hover and keyboard outline. Disabled actions retain their state and use 45% surface opacity. Native checkboxes and application switches retain their standard artwork. The session-header decorative wave is hidden on the settings screen. The mesh continues through native menu padding at both edges, including below the settings pane.

M Sessions or Escape restores the retained session list, disclosure, drafts and saved scroll offset. Settings keystrokes do not filter session titles or invoke request actions. Tab/Shift-Tab and Up/Down wrap through visible enabled settings controls, including text inputs; Left/Right on a navigation tab selects the adjacent tab. Enter/Space activates the focused nontext control. Text fields use the native field editor, including Command-A/X/C/V; typing and Return remain in the editor. Shortcut recording consumes its own keys. Switching tabs ends recording and commits field editing. Closing the menu exits settings. The last selected tab remains in memory, not on disk. Snapshots continue updating actual controls, including Telegram connected/setup replacement; pane refresh does not replace an unchanged active view or discard its field editor.

G: normal GTK Window560 initial width, toolbar ToolButtons (system/app-grid/custom robot/mail-send symbols), nonhomogeneous Stack of four same-named pages;18page padding,10vertical spacing. Page change/snapshot triggers preferred-height resize, preserves position. Window manager can affect actual decoration/resize behavior. Close hides, retains controls. GNOME still uses a separate settings window.

H: the [in-popup settings prototype](../platforms/html.md#html-inline-settings) uses the same navigation concept with simulated setup states. Sessions/Escape restores list scroll, disclosure, drafts and focus to the gear. Mock animation/application preferences affect fixture rendering; OS setup, shortcuts, credentials and Telegram are not connected to production services. H has responsive wrapping and Home/End tab navigation; M uses fixed native pane geometry. H now matches M/G direct unlink behavior; its replacement/activation states remain simulated.

**SET-02 (H/M):** Opening Settings MUST retain the current session view state and replace its visible content within the same popup. Returning to sessions MUST restore its saved scroll position and drafts. Settings input MUST NOT change the session title filter. This is not a GNOME lifecycle requirement.

Acceptance: open each tab without increasing the native window count; switch Telegram between connected/setup/connected without blank content or losing the token draft; type in the token field, Tab out, and Escape back to the original session scroll offset. The native offscreen renderer checks these outcomes in both appearances. Native NSMenu tracking, clipboard/IME, VoiceOver and OS activation still require interactive runtime verification.

Legacy domain migration copies missing values once but not OS notification authorization/first-launch results. Setup keeps IntegrationSetup.<agent>, error strings, notification error, FirstLaunchSetupCompleted. Tokens via Security.framework Keychain. Shared domain default loginDisabled, animationtrue, shortcutNone, empty catalog.

G preferences.json under state directory: applications,animation,shortcut; corrupt/missing file falls back to defaults. Login determined by existence of `$XDG_CONFIG_HOME/autostart/ai-agent-monitor.desktop` (default~/.config), created/removed by control. Token via `secret-tool` Secret Service, never JSON; missing/locked keyring yields explicit error. Telegram nonsecret config in state `telegram.json`. State home M `~/Library/Application Support/AI Agent Monitor`; G `$XDG_STATE_HOME/ai-agent-monitor` or `~/.local/state/ai-agent-monitor`. <a id="settings-web"></a>
## Web pane (macOS)

The fifth tab controls the resident HTTP server. Width460pt; the enabled pane uses380pt plus28pt per address and an optional40pt connecting/error status row. While off it collapses to92pt (132pt if a startup error needs to be shown), displaying only the heading, Web access switch and subtitle. Address rows, QR, countdown, connection instructions, QR/link buttons, paired-browser count and disconnect explanation are hidden as a unit; they appear when enabled. Changes resize the existing popup immediately. Web access title and switch share the top row; subtitle explains phone browser access. The switch is off on each application start, starts `0.0.0.0:8765`, and revokes browser sessions when disabled. The single Web access switch starts the local listener and automatically attempts an experimental, account-free Cloudflare Quick Tunnel using installed `cloudflared`. There is no separate Remote access switch or heading. Connecting/reconnecting or failure text appears below the subtitle; a healthy tunnel is represented by its HTTPS address in the shared address list. A missing connector or tunnel startup failure leaves the LAN listener enabled and reports the failure. The first received HTTPS origin is automatically selected for the QR. Turning Web access off stops all paths and revokes browsers. Web access is off on application start; CLI tunnel-stop remains available for separately stopping the remote path. All addresses are separate28pt radio rows in a natural-height document without an inner scroller. The healthy-state gap below the subtitle is12pt; empty tunnel-status text reserves no space. The existing settings/window height grows and shrinks with address count; only the outer settings viewport scrolls when the screen cannot fit the complete pane. Each address row has a muted right-aligned descriptor: Local network, Cloudflare tunnel, or This computer for loopback. Long addresses truncate in the middle in M, at the end in H, and retain the full URL in a tooltip. Selecting a row changes the QR and Copy link destination. Routine status polls preserve row identity and selection; interface reordering preserves the selected URL. There is no nested address popup. Below it: a200×200pt black-on-white QR, a determinate progress bar with remaining seconds directly underneath, instructions, New QR code and Copy link; paired-browser count and a brief HTTP/local-network explanation follow. Action controls use the common glass treatment. A failed bind/control request is displayed inline. IPC runs on a worker thread; the pane polls results on the main thread and refreshes status every two seconds while visible. While this pane is visible and Web access is on, an expired or consumed pairing secret is automatically replaced through Pair. A local monotonic countdown updates between status polls; the120-second bar empties toward zero and resets on renewal. The old image stays visible while renewal is in flight, but an expired link cannot be copied. A failed renewal displays the transport error and retries with the same polling interval. Turning Web access off hides the QR and countdown.

QR and link MUST contain the same selected address and single-use pairing token; renewal MUST invalidate the old token. Used/expired tokens MUST remove the QR and disable Copy. A server stop MUST revoke all browser sessions. Native text and code remain readable in either appearance; QR modules use absolute sRGB black.

GNOME currently exposes management through CLI (`web tunnel-start` / `web tunnel-stop` for remote mode) rather than a settings tab; the prototype now has five simulated panes, including Web. Its Web pane starts disabled, automatically simulates a Cloudflare connection after enabling Web access, and shows inline LAN/loopback/remote radio addresses, a QR and a120-second renewing countdown. QR fixtures encode reserved example addresses; Copy link matches the selected fixture. Demo renewal alternates two synthetic tokens and does not implement authentication. No service starts and no network pairing occurs. Telegram setup simulates checking and waiting for activation; Open bot completes that activation, and Cancel during replacement keeps the old bot. Unlink is immediate, matching the native control. The settings container receives focus on entry without highlighting Back. The remote HTML host hides those mock settings controls. Browser behavior, expiry, persistence, errors and transport bounds: [Web access](../../web-access.md). Sources: `src/macos/web_settings.rs`, `src/web/server`, `src/macos/menu.rs` settings navigation; native visual and web transport tests.
